# Valhalla Freight v0.12.7 — manufacturer workspaces

## Architecture and changes

The existing React/Vite client uses an AuthProvider and Layout navigation. FastAPI mounts domain routers, SQLAlchemy manages database access, and startup applies additive PostgreSQL upgrades through `app/db/schema_updates.py`. Manufacturer accounts use the existing `users.customer_id` foreign key as their company boundary; no parallel tenant identifier is introduced.

- Manufacturer navigation omits Prospect Analysis, Automation Center, Capacity Center, Carrier 360 administration, Integration Hub and Customer Portal administration. Broker/admin navigation remains available.
- The manufacturer administrator controls Pricing Engine availability for all users in that company. Ordinary manufacturer users can view enabled pricing; creating company pricing rules requires manufacturer-admin access. Global rules remain broker-managed.
- Company name and PNG/JPEG logo are stored in a new company-keyed settings table. Sidebar branding refreshes immediately after saving and within 30 seconds/on focus in other sessions.
- My Profile saves the display name immediately and supports password changes with current-password verification. Email and role are displayed read-only; this prevents self-service privilege escalation.
- System Settings lets manufacturer administrators update shared branding and pricing availability; other manufacturer users see read-only settings.
- Backend module permissions use the current database role, not the token's role claim. Manufacturer ORM queries (including aggregate queries and direct ID lookups) are scoped to the linked company; writes validate ownership and related shipment/quote references. Existing broker/admin sessions remain unscoped. Customer portal users are denied internal domain routes.
- Existing quote rating, booking, lane validation and BOL document rendering modules are retained. A pre-existing direct shipment form omitted the freight editor's required props; it now passes and serializes all freight lines correctly.
- Build configuration now uses ES2021, bundler module resolution and Vite environment types. The frontend dependency lockfile is included for reproducible Docker installs.

## Non-destructive database upgrade

Startup creates `company_workspace_settings` without changing or deleting existing tables, records, document volumes, or schema upgrade statements. Legacy manufacturer user-level settings are copied once per company, preferring a manufacturer-admin record, then the lowest user ID. Original user-level settings are retained. Repeated startups do not overwrite company settings. Unlinked manufacturer accounts are denied access until an administrator assigns their existing customer/company ID.

Manufacturer roles are `manufacturer_admin` and `manufacturer`. Accounts in the same company must share the same `users.customer_id`. Existing account provisioning remains unchanged; this release does not create or reset login accounts. Company branding changes the workspace display name, not the broker's legal/customer master record.

## Local Docker upgrade

Use your EXISTING ValhallaFreight project directory and its existing Compose project name so Docker reuses the existing named PostgreSQL and documents volumes. Keep your current `.env` configuration. Make a database backup before upgrading:

```powershell
docker compose exec -T db pg_dump -U valhalla_freight -d valhalla_freight -Fc -f /tmp/valhalla-before-v0.12.7.dump
docker compose cp db:/tmp/valhalla-before-v0.12.7.dump ./valhalla-before-v0.12.7.dump
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 backend
```

Open http://localhost:5173. No database reset is necessary. The legacy reset PowerShell script now performs a volume-preserving rebuild/restart.

## Validation

- Frontend: `npm ci` then `npm run build` from `frontend`.
- Backend syntax: `python -m compileall -q backend/app`.
- Backend regression suite: install `backend/requirements.txt` plus `pytest`, then from the project root run `PYTHONPATH=backend python -m pytest backend/tests -q` (PowerShell: set `$env:PYTHONPATH="backend"` before the pytest command).
- Tests use isolated SQLite databases and cover shared company settings, read-only manufacturer access, disabled pricing, cross-company list/detail/aggregate/write isolation, broker/admin behavior, restricted modules, profile/password updates, logo validation, and multi-class quote-to-shipment/BOL assignment with mocked carrier services.
- PostgreSQL migration execution, Docker container startup, browser Google Places selection and print/PDF visual output require local verification; Docker/PostgreSQL are unavailable in the development environment. Carrier rating/booking integrations were mocked in regression tests and were not contacted.
- The build emits non-blocking dependency directive and bundle-size warnings.

## Local acceptance checklist

1. Log in as broker/admin; check existing navigation, Quote Studio and existing shipments.
2. Log in as a linked manufacturer administrator. Save a company name/logo and enable pricing. Confirm immediate branding/navigation refresh.
3. Use a second manufacturer user linked to the same customer: confirm shared branding, enabled pricing and read-only System Settings. Another company's users must not see those settings or shipments.
4. Disable pricing as the manufacturer administrator. Confirm direct Pricing Engine navigation/API requests are denied after the permission refresh; quote rating remains available.
5. Update a profile name and password; sign out/in using the new password.
6. In Quote Studio, create a multi-class quote, confirm Google-verified facilities, approve/create the shipment, and print the BOL. Repeat direct shipment creation with multiple freight lines.
7. Rebuild/restart containers, verify settings and existing PostgreSQL records remain present.
