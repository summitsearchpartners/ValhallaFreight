# v0.19.4 — Safe Load arrival photos and local OCR

## Update your running computer

Keep your existing root .env, PostgreSQL volume and document volume. Copy the inner ValhallaFreight project files over your existing project. In the old Safe Load Metro window press Ctrl+C. Then, in a separate PowerShell window:

```powershell
Set-Location C:\GitHub\ValhallaFreight
docker compose -p valhallafreight up -d --build
```

The backend image installs Tesseract English OCR plus the Python barcode reader. This build requires package-download internet access. Startup adds two new evidence/contact tables; no existing tables or data are reset. Do not run docker compose down -v.

Restart the phone application from a separate PowerShell window:

```powershell
Set-Location C:\GitHub\ValhallaFreight\safe-load-mobile
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-SafeLoad.ps1 -ComputerIP 192.168.1.195
```

Use Expo Go SDK 58 on Android and scan the new QR code. In Safe Load use TMS server URL http://192.168.1.195:8000 and your Manufacturer login. Leave Docker and Metro running. The existing local-network firewall rules remain applicable. Refresh the desktop page with Ctrl+F5.

## Broker setup

Open Safe Load for the shipment, save a monitored broker phone number under Warehouse escalation contact, and review/approve the dispatcher assignment. Contact details can also be saved for an already approved assignment. The photo-submit release action requires this phone contact and current broker approval.

## Warehouse flow

1. Open the shipment. Confirm the dispatcher license photo is visible. Images are normalized to JPEG with orientation correction, transparent backgrounds composited onto white, and metadata removed. Android loads the authenticated image into an in-memory data URI to avoid native authenticated-image/cache rendering issues. Loading errors are shown explicitly. A truly black/unreadable stored original cannot be reconstructed: ask the dispatcher to replace it through the carrier invitation.
2. Tap Take driver ID photo and capture the actual physical ID, in focus and without glare. Include full printed name, number, issuing state and expiration. A photograph of the PDF417 barcode on the back is also supported for extracting those fields; compare the actual physical front/portrait to the dispatcher photo yourself.
3. Tap Take truck VIN photo. Photograph the VIN on the truck, not a copied label supplied separately.
4. Review both image previews. Confirm you visually compared the arriving person and physical ID with the dispatcher photo.
5. Tap SUBMIT PHOTOS & VERIFY / RELEASE. The server reads both images locally and compares name, license identifiers/issuer/expiration and the 17-character VIN to the current approved assignment. It accepts no caller-supplied OCR text. A successful match records CONFIRMED, releases the Safe Load hold and records pickup in the shipment, in one database transaction.
6. A mismatch or unreadable extraction records REJECTED, invalidates broker approval, blocks release and creates an immediate in-software broker notification. The app displays the saved broker number with a Call broker button. The broker must resolve/correct and reapprove before another submission.
7. If the person or ID portrait is visibly wrong, use REJECT · person / ID photo does not match. This explicitly records the rejection and notifies the broker; do not mark the visual comparison as passed.

The desktop Safe Load popup also accepts arrival image uploads/capture and one-submit verification, shows result reasons, the call number and the recorded arrival photos for authorized review. Older barcode-scanner workflows remain available as a separate alternative with their existing scan and release checks.

## What the automated checks establish

This release performs local barcode decoding and conservative OCR/text matching, plus the warehouse operator's explicit visual identity comparison. It does not perform automated facial/portrait authentication, DMV validation, ID authenticity detection, VIN ownership checks or liveness verification. Do not treat a green text match alone as proof of identity.

The OCR fallback recognizes labeled license number fields (DL/License number or numbered fields), FIRST NAME/FN/2, LAST NAME/LN/1, issuing-state name or ISSUING STATE: XX, and EXP/4B date fields. Unsupported card layouts, ambiguous fields, glare, blur, missing labels and OCR errors fail closed. The PDF417 photo option can read fields more reliably when the full barcode is sharp. Real state IDs and actual device cameras still need pilot testing. We do not silently guess/correct ambiguous license characters or VINs.

Input validation errors such as missing files, excessive size, stale assignment, missing contact or missing visual confirmation keep the load on hold and explain the required correction. These are distinguished from an actual submitted identity/VIN mismatch. Unreadable supported photo content is rejected and reported to the broker.

Each photo is limited to 8 MB and 16 megapixels before normalization. No external OCR/AI provider or API key is used. ID and VIN evidence is encrypted in the existing document volume. Only authorized users for that shipment can retrieve it; views and decisions are audited. Full license numbers/raw OCR text are not placed in notifications. Evidence is retained until an owner-defined retention/deletion policy removes it; this release does not silently delete audit evidence. Temporary native captures are deleted on retake, submission/queue change, sign-out or component cleanup. SecureStore contains only the existing server/token settings, not photo data.
