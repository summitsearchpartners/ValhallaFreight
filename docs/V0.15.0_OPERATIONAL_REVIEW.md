# Valhalla Freight v0.15.0 — Operational clarity and workflow review

This release applies Dave's review to the uploaded v0.14.1 project. Existing account roles, manufacturer support windows, shared branding/settings, Google address confirmation, freight classifications, shipment booking and BOL flows remain in place.

## Changes by finding

| Finding | Implemented behavior |
| --- | --- |
| Quote Studio freight row overflow | Each freight line is a wrapping grid with usable minimum widths. Quantity, weight per unit, length, width, height and Class remain available. The rate sidebar stacks below entry on smaller windows. Narrow-screen padding and density-card wrapping were adjusted. |
| On-time percentages with zero shipments | Carrier 360 returns no actual percentage when the qualifying denominator is absent. Network/profile scorecards show **No qualifying shipments**. Stored sample/reference benchmarks are labeled separately in Performance. The network average uses total on-time deliveries divided by total qualifying deliveries, rather than averaging carrier percentages. Claims ratios also require a shipment denominator. |
| Contradictory connection status | API/EDI capability flags no longer mean connected. Integration Hub distinguishes provider definitions, installed live adapters, credentials configured, historical verification and a recent successful live check. Each connection shows its last successful live check. Definitions imported from OpenAPI are not live adapters. |
| Misleading system health | The sidebar reports the app/database response and separate current/unverified external checks. It no longer claims all services are operational. A configuration-only review never creates live health. A live check is current for 15 minutes; credential or endpoint changes invalidate previous verification. |
| Empty operational screens | Visibility, Analytics and Claims explain why data is missing and offer links to quote creation, shipments, freight import or claim filing from an affected shipment. Loading errors are distinguished from empty records on the updated screens. |
| Automation descriptions without operational history | Automation Center now shows actual newly recorded connection checks, configuration reviews and Dayton tracking refreshes, their outcomes, last execution, unresolved failures and attention links. Supported failed checks/tracking refreshes have retry actions. Capability descriptions are secondary. |
| Long booking form / carrier context lost | A persistent summary keeps the selected carrier, sell price, cost, gross profit, margin, lane and missing requirements together with the booking action. The form is divided into references/freight, facilities and services. Existing ZIP/address verification remains enforced. |
| Hazmat fields shown for ordinary freight | Emergency fields appear beside the hazardous-materials selection only when selected. Hazardous shipments require emergency contact and phone on both the booking screen and backend. |
| Prospect file guidance missing | Prospect Analysis offers a downloadable CSV template, accepted formats/size limits, required and optional columns, a sample-row preview, column mapping and full-file validation before explicit analysis. Results describe uploaded rows rather than claiming an unknown file period is annual spend. |
| Evening greeting / reporting date mismatch / technical labels | Greetings follow the selected display timezone and time of day. Reporting end dates use that timezone's calendar date; chart boundaries are explicitly labeled as UTC creation dates. Database-generated UTC timestamps are formatted separately from local appointment values where updated. Pricing uses business labels such as **Markup percentage** and **Verify shipping addresses with address suggestions**. |
| Command Center next actions | **What needs your attention today?** links to overdue delivery commitments, missing carrier references, pending carrier-bill review, failed operations and connection setup/verification. A failed queue request is not presented as an all-clear. |

## Operating the new workflows

### Carrier performance

Open **Carrier Network**, then a carrier's **Performance** view. Actual pickup/delivery percentages require both actual and qualifying commitment timestamps. The stored reference benchmark is not used as a fallback for actual performance. No shipment history means no measured percentage, rather than an artificial 0% or 96.2%.

### Connection health and automation

Open **Integration Hub**. Provider definitions and imported specifications describe possible connections; currently Dayton is the installed live carrier adapter. Save credentials, then run its authentication test. A successful live vendor response records verification and a successful-check timestamp. A failed check remains a review item; a successful retry clears that operation's older failure from the attention count. Changing credentials or endpoint settings requires verification again.

Generic configuration reviews explicitly report that a live vendor call is not implemented. They do not update successful-check timestamps or make a service healthy. Recent status is refreshed periodically while the updated network/integration/status views remain open.

Open **Automation Center** directly at `/automation` if it is hidden from your current menu configuration. Only supported connection-check and tracking-refresh failures can be retried. Company permissions and selected support-window context are enforced. Booking, pickup submission and payment actions are not automatically retried. Tracking refresh retries do not duplicate already observed events; carrier timestamp offsets are normalized to UTC.

Run history starts with new activity in this release. It is not backfilled from old descriptive feature cards. This screen is not a background scheduler and does not imply that email-to-quote or unsupported adapters are executing.

### Prospect Analysis

Open `/prospects` as an authorized Valhalla Admin/broker. Download the template or use `docs/templates/Valhalla_Prospect_Template.csv` from this project.

- Accepted: CSV, XLSX, XLS; one worksheet/header row, 1–50,000 shipment rows, maximum 10 MB.
- Required: freight spend (non-negative dollars), weight (positive pounds).
- Optional: origin ZIP, destination ZIP, freight class and carrier. Keep ZIPs as text to retain leading zeroes.
- Choose a file, inspect the first 10 rows, map source columns, validate the full file, then run analysis. Invalid rows and missing mappings are reported before analysis; invalid values are not silently converted to zero.
- Totals apply to the uploaded rows. They are not annualized and no savings estimate is invented without comparable pricing.

### Booking

Open a selected quote. The summary remains visible while scrolling. Complete saved or Google-confirmed addresses matching the rated ZIPs, review individual freight classes, and select services. If hazardous materials are selected, complete the conditional emergency details. The existing approval action creates the shipment and BOL through the same booking flow.

## Data-preserving Docker upgrade

Use the **same existing installation directory and Compose project name**, and retain your current `.env`. This ZIP contains application source and example configuration; it does not replace your private local configuration or database volumes.

Optional PostgreSQL backup before copying files:

```powershell
docker compose exec -T db pg_dump -U valhalla_freight -d valhalla_freight -Fc -f /tmp/valhalla-before-v015.dump
docker compose cp db:/tmp/valhalla-before-v015.dump ./valhalla-before-v015.dump
```

Copy the updated project files into your installation, then run:

```powershell
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 backend
```

Open http://localhost:5173 and refresh. Do not delete database/document volumes or run `docker compose down -v`.

Startup adds the `operation_runs` table through the existing SQLAlchemy metadata creation path. Existing schema update statements, seed behavior and Docker volume configuration are preserved. No existing shipments, quotes, settings, accounts, benchmarks or migration history are removed or reclassified.

## Local acceptance checklist

1. Resize Quote Studio, add multiple freight lines, edit Class and confirm every dimension remains usable.
2. Compare a carrier with no history to one with qualifying deliveries. Verify the denominator and separate benchmark label.
3. Check Dayton before/after credential configuration and a real authentication check. Compare Network, Integration Hub and sidebar wording; verify last successful check.
4. Exercise an intentional failed check, then fix its configuration and retry. Confirm a new run appears and the old failure is no longer outstanding.
5. Upload the prospect template, then a file with renamed columns and one with invalid numeric values. Confirm preview/mapping/validation precede analysis.
6. Open a quote, confirm addresses, toggle hazardous materials, and verify conditional fields and requirements. Complete a normal shipment/BOL regression.
7. Check Visibility, Analytics and Claims with no records; follow their actions. Review an overdue shipment from Command Center.
8. Change display timezone/time format and verify the greeting, header time and labeled report end date. Confirm manufacturer users and admin support windows retain their company scope.

See `VALIDATION_V0.15.0.md` for executed checks and remaining local checks.
