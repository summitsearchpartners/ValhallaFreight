# Valhalla Freight v0.12.8 — Accounts, Roles & User Activity

## Where to start

Sign in with your existing Valhalla Freight administrator account. Open **Administration → Users & Company Access**. Existing accounts whose stored role is `admin` are now labeled **Valhalla Freight Admin (Super User)**; your current login remains valid.

Use **Add company** if the company does not exist, then **Add user**. Choose the role, select the company/portal, and set the initial password. Credentials are created immediately; no automatic email is sent. The account directory includes role, company and status filters, last login, last seen, edit/password-reset controls, account removal and user activity history.

## Roles

| Selector label | Stored role | Access |
| --- | --- | --- |
| Valhalla Freight Admin (Super User) | `admin` | All existing internal modules; all companies; create/edit/disable/remove accounts; assign roles/portals; view activity; manage company settings and integration connections; open any customer portal with explicit company context. |
| Manufacturer Admin | `manufacturer_admin` | Company-scoped manufacturer workspace plus Integration Hub and Customer Portal administration; manage own branding, pricing visibility, shipping locations, contacts and portal margin-protection settings. Cannot create users, assign roles, inspect global credentials or administer another company. |
| Manufacturer | `manufacturer` | Manufacturer operations for assigned company; enabled Pricing Engine is read-only; no Administration section, Integration Hub, Customer Portal administration or account management. Shared system settings remain read-only. |
| Customer | `customer` | Only the assigned customer portal, its freight records, documents, invoices and margin settings. No internal workspace or account administration. |

Existing legacy broker accounts remain supported, but are not offered as a new role selector option. They do not receive account-administration privileges. Only `admin` accounts can create or modify logins.

Manufacturer and Customer roles require an existing company assignment. Valhalla Admin accounts have global company access. One user currently has one role and one company assignment. Updating role, company or enabled status changes backend permissions on subsequent authenticated requests; permissions are read from the database. Removed/disabled accounts cannot use their previous tokens. Password resets change login credentials; already issued sessions for an otherwise active account retain their normal expiry.

An administrator cannot remove/demote/disable their own super-user account. The system also protects the last active Valhalla Admin. Existing company freight data is retained when a login is removed. Activity snapshots survive removal. Startup no longer recreates the default admin when another active admin exists, and an explicitly removed demo customer login is not recreated.

## Manufacturer integration isolation

Each API integration connection now has an optional company owner. Existing rows remain global Valhalla connections. Manufacturer Admins see and configure only connections belonging to their assigned company. Integration credentials remain encrypted and responses expose only configuration flags and masked hints.

Company-owned Dayton connections do **not** inherit the broker's `.env` username, password or account. Enter that company's own API credentials to enable its live API access. Quote, booking and carrier integrations resolve the appropriate company connection. The freight rating calculation, multiple handling-unit classifications, shipment creation and BOL renderers are retained.

Valhalla Admins can use the **Integration account** selector to manage a specific company. The default view lists all integration accounts; selecting Manage on a company's connection switches to its context. **System Settings → Settings account** similarly selects the manufacturer whose branding/pricing visibility the super user wants to edit. **Customer Portal → Open customer portal** opens the actual selected portal with a return link to administration.

Built-in carrier adapter software remains installed even if its account connection/configuration is removed; opening the hub can recreate an empty built-in connection shell. This does not restore deleted credentials.

## Last login, last seen and activity

- Last login records successful authentication in UTC.
- Last seen records login plus visible-session presence. The client sends a heartbeat every 60 seconds while the page is visible and has received interaction in the previous two minutes. It is a recent-activity indication, not a guarantee that a person is at the keyboard.
- Activity records successful logins, sign-outs, page views, account changes and authenticated API requests with method/path/status. Heartbeats and account-directory polling do not flood the activity list.
- Only Valhalla Admins can read the activity feed. It supports per-user/company filtering and older-page loading. Timestamps display in the viewer's local timezone.
- Passwords, credential payloads, query strings and request bodies are not stored in activity. History begins with this release; previously unknown last-seen values display **Never**.

## Architecture and database upgrade

The application continues to use React/Vite, FastAPI domain routers, SQLAlchemy sessions and the existing `users.customer_id` company boundary. Additive startup changes add `users.last_seen_at`, `integration_connections.customer_id` and its index. SQLAlchemy creates the new `user_activity` table, which stores historical identity snapshots without requiring a surviving login row. Existing schema update statements, company settings, PostgreSQL rows, Docker volume names and Compose configuration are retained.

The backend guards account administration separately from company administration. Server-side company query/write scoping also covers integration connection IDs and credentials, preventing direct-URL/API access across company boundaries. A super-user company context is explicitly authorized on the server.

## Safe local Docker upgrade

Extract the project into your **existing ValhallaFreight directory** and keep your current `.env`. Use the same Compose project name/directory to reuse the existing PostgreSQL and documents volumes. Recommended backup and rebuild:

```powershell
docker compose exec -T db pg_dump -U valhalla_freight -d valhalla_freight -Fc -f /tmp/valhalla-before-v0.12.8.dump
docker compose cp db:/tmp/valhalla-before-v0.12.8.dump ./valhalla-before-v0.12.8.dump
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 backend
```

Open http://localhost:5173 and sign in with your existing Valhalla Admin login. No volume deletion or database reset is needed.
