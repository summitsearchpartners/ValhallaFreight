# v0.14.1 — Correct manufacturer portal access

## Correction

Portal Access previously opened every selection in the Customer Portal. Selecting a manufacturer company now opens its full **manufacturer workspace**, starting at **Command Center**, with the company's saved name/logo, manufacturer navigation, Quote Studio, shipments, customers, finance, claims, analytics, Integration Hub, My Profile and System Settings. Pricing Engine visibility follows that manufacturer's saved setting.

Customer records under a manufacturer continue to open the separate **Customer Portal**. The directory identifies manufacturer and customer selections. The verified server response determines which workspace opens.

## Administrator identity and company context

You remain signed in as the real Valhalla Freight Admin. The manufacturer's navigation uses its Manufacturer Admin view, while the account control and support banner identify **Valhalla Freight Admin · Super User**. No manufacturer login is substituted, no user role/company assignment is changed, and no customer password is required.

The selected company context is retained as you navigate and refresh. Each support window has its own grant and selected manufacturer, so two manufacturer windows can remain open without changing each other or the original administrator window. The banner shows the manufacturer, expiry, **Switch portal** and **End support session**. Ending support or using the profile menu's end-session action closes that support window and leaves the original admin session signed in.

Company branding and Pricing Engine changes apply to the selected manufacturer. Personal profile/security/preferences continue to belong to the real admin account. User login creation remains in the original Valhalla Administration workspace.

## Backend enforcement

Verified grants now record whether they open a manufacturer workspace or customer portal. Manufacturer workspace API requests validate the real admin, selected company, grant type, expiry and revocation, then apply company scoping to reads/writes, including that manufacturer's own customers. A customer portal grant cannot be reused to open a manufacturer workspace or another company. Customer portal endpoints reject manufacturer grants. Normal Valhalla Admin access in the original window remains unrestricted.

Existing password verification, optional Google Authenticator, 15-minute grants, single-use 60-second tickets and real-admin User Activity logging are retained. Activity now identifies the opened portal type.

Previous migration statements, PostgreSQL/document volume configuration and seed behavior are retained. No existing freight, accounts or settings are reset. Do not use `docker compose down -v`.
