# v0.19.16 — Upright driver-license photos

## Automatic orientation

New dispatcher, front-ID and back-ID uploads apply EXIF orientation, then a conservative local text-direction check before encryption/storage. The existing local RapidOCR text-line direction classifier/recognizer is reused, with Tesseract orientation/text fallbacks. Rotation is limited to quarter turns and only applied when readable lines agree strongly. No face detection, expected driver data or external OCR service is used to choose orientation. If there is too little or conflicting text, the photo is not forcibly rotated; use the preview controls.

The supplied sideways ID example was privately checked and correctly identified as needing a 270-degree clockwise turn. It is not included in this project. That result is not a guarantee for every obscured or unusual document layout.

## Before uploading or accepting a camera photo

- The dispatcher submission form has Rotate License Left/Right controls. These rotate actual pixels in the file that is uploaded; they are not just a CSS effect. Check that the text is upright before Submit Driver Assignment.
- The phone/tablet camera's Review Photo screen has Rotate Left/Right before Accept Photo. Rotation updates the actual accepted JPEG, retaining the crop. Retake and Cancel behavior remains. A rotation finishing after Cancel is discarded rather than re-opening the camera.
- After QA, retained local captures can switch to the server's corrected saved preview without disappearing. A newly retaken photo remains local until its own submission, so old evidence cannot replace a new capture preview.

Automatic correction happens at server upload time; the local camera review is still a manual guided capture. This does not reintroduce automatic shutter capture.

## Existing saved photos and history

Dispatcher previews and the app's saved-ID data previews can derive an upright display of older sideways images. Broker onsite ID requests use the optional `upright=true` preview. Existing encrypted files and custody hashes are not rewritten. Original onsite binary access remains the default without that query parameter; the VIN image is not automatically modified by this preview option.

The broker's dispatcher/onsite photo viewers also have Rotate Left/Right for viewing. Those controls are labelled view-only, do not persist a change to stored evidence and retain full-size image opening. They reset when the viewed photo changes. No reassignment, resubmission or release is needed just to view an old photo upright.

Identity matching, the local VIN reader, rejection notifications, callback contacts, release approvals, receipts and roles remain intact. No database migration, dependency upgrade or volume reset is required.

## Install and test

Preserve .env and your Docker database/document volumes. Copy this ZIP's inner ValhallaFreight contents over C:\GitHub\ValhallaFreight. Update backend, frontend and safe-load-mobile together. The ZIP contains source, not your live database or identity photos.

Stop the OLD Metro window with Ctrl+C, then:

```powershell
Set-Location C:\GitHub\ValhallaFreight
docker compose -p valhallafreight up -d --build
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\safe-load-mobile\Start-SafeLoad.ps1 -ComputerIP 192.168.1.195
```

Scan the NEW QR on the phone, or press **a** in Metro with the Android emulator running. Verify **App v0.19.16**. Server URL remains http://192.168.1.195:8000 unless the PC's IP changed.

Check an existing sideways dispatcher photo in the broker portal. For a new test load, upload a sideways/upside-down image, use the rotate preview controls and submit. On the phone, take an ID photo, rotate it on Review Photo, Accept and Submit. Reopen the load to check the saved preview. Confirm that leaving/reopening and viewing rotations do not change release status or custody integrity. Use a new test load for QA; earlier rejected loads still require broker authorization.

Physical Android/iOS rendering and camera operations still need your device check. No physical phone, live Docker/PostgreSQL deployment or native store bundle export was available in this environment. See RELEASE_CHECKS_V0.19.16.md for executed tests.
