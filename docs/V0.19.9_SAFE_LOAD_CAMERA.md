## Driver-license and VIN scanning

The camera now explicitly requests autofocus, remounts per capture mode, supports torch/zoom, and keeps scan feedback on the camera screen. It no longer closes/latches permanently on the first invalid reading. Live barcode events are validated on the backend; incomplete/malformed readings stay open and can be retried.

If the device's live callback misses the barcode, the app automatically captures and decodes a camera frame through the authenticated backend. **Scan current frame** triggers that same real decoder immediately. This reads barcode symbols using the installed local ZXing engine, not OCR masquerading as a barcode result. Camera frames are transient; no photo-library picker is used. The full barcode should fill the guide, be in focus and free of glare.

- **Scan back of driver license · PDF417** accepts the entire back-of-ID PDF417. The server extracts/validates the required identity fields and returns the existing preview, including DOB when encoded. DOB/raw barcode remain transient as documented in v0.19.8; required encrypted evidence photos can naturally contain the printed DOB. Partial scans do not become accepted evidence.
- **Scan truck VIN barcode** supports the common Code39/Code128/Code93/Data Matrix/QR live formats and the backend frame decoder's supported symbols. VIN validation is centralized on the server, including common AIM symbology prefixes and Code39 start/stop marks. A QR URL or arbitrary string is not treated as a VIN: one canonical 17-character VIN is required.
- A successful scan returns to the load and visibly shows the extracted ID or VIN. Both required onsite photos are still necessary. Submit Photos sends the scanned structured data through the existing identity/expiry/VIN comparison, evidence storage and custody/release checks. The scan itself never releases freight.
- Multiple different readable barcodes in one frame are rejected. Show only the current license or truck label. A stale/closed assignment cannot adopt a later camera result.

Camera scanning still requires network access to the TMS. Expired sessions, unavailable camera/permissions and server problems appear as visible status messages with Cancel available. Unsupported/missed real card layouts remain holds for broker review; a barcode is not facial, DMV or VIN-ownership authentication.

## Guided ID photo and automatic capture

**Take driver ID photo** opens a card-shaped outline. Place the full physical card against a contrasting background with all four edges visible. The backend checks for a centered card-shaped quadrilateral, sufficient document size, lighting and sharpness. Two consecutive ready frames must also remain geometrically stable before the app automatically adopts the latest captured image.

This is an image-readiness heuristic, not identity approval, a timer or a guarantee that every layout/glare condition is readable. A rectangle without valid identity fields will still fail final QA. Portrait phone orientation gives the ID the most useful space. The frame guide adapts to the preview size; precise camera-preview/capture geometry and threshold tuning require real-device acceptance testing.

**Take Photo** remains available as the manual fallback, and **Cancel** remains at the top of the camera screen even while a check is running. You can turn auto-capture off and use the manual shutter. Torch and zoom assist both ID and barcode capture. VIN photos remain manual so the worker can choose the correct truck label. An unavailable readiness service disables automatic capture and directs the user to Take Photo; the backend connection and normal evidence/QA requirements still apply.

Frames are taken only while that camera screen is open. Intermediate readiness/scan frames are processed transiently by the same authenticated TMS and deleted from the phone cache after processing. The HTTP framework can spool uploads to temporary storage; these frames are not added to persistent shipment document storage. They are not saved as shipment evidence or sent to an external vision provider. The adopted ID/VIN photos follow the existing capture-event and encrypted evidence workflow. Cancellation or assignment change discards a pending temporary frame and cannot approve a load.

## Refresh, sign out and login

The warehouse queue's refresh button shows **Refreshing shipments…**, an activity indicator and a timestamped shipment count after a successful response. Pull-to-refresh is also available. Background polling remains quiet. Errors keep the existing queue visible and display the connection failure instead of showing a false success timestamp.

The lock-mark Safe Load header and sign-out control are fixed above the scrollable content. **Sign out** is at the top right on authenticated app screens. The login screen now uses the matching lock logo, orange/navy identity, pickup-control headline and evidence/release/custody feature tags. Sign-out clears local scan/capture state and the stored session token as before.

## What remains intact

Quote Studio, LTL/truckload booking and BOLs, pricing privacy, role/company permissions, Muse flows, broker callback profile, automatic QA, rejection notifications, broker exception authorization, confirmation numbers and custody snapshots remain in place. Previously rejected loads remain held until broker resolution; a new readable scan cannot erase the earlier rejection. No data, migration or volume changes are introduced.
