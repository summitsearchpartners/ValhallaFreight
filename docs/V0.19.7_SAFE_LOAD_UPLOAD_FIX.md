# v0.19.7 — SDK58 onsite camera upload fix

## What caused the error

The phone submitted legacy React Native `{uri, name, type}` multipart objects. Expo SDK58's installed FormData serializer rejects that object with `Unsupported FormDataPart implementation` before the photos reach the backend. The same exact error was reproduced in the new regression tests against the installed Expo serializer.

The app now submits `expo-file-system` File objects using explicit `expo/fetch`. Expo reads the actual camera-file bytes and creates the multipart boundary. The driver ID/VIN pictures and revision/capture metadata use the existing backend endpoint unchanged. See Expo's official upload examples: https://docs.expo.dev/versions/latest/sdk/filesystem/ and https://github.com/expo/image-upload-example.

The phone validates that both local captures still exist and each is under the backend's 8 MB limit. Failed transport or server responses retain the captures for retry and display a more specific error. Photos are cleared after successful server receipt, including a QA rejection, because the broker can then review the stored evidence. An ambiguous/lost response asks the employee to refresh the load before retrying.

The automated matching, shared broker callback profile, rejection notification, broker review/authorization, phone status refresh, encrypted evidence and custody chain from v0.19.6 are retained. No schema, migration, integration credential, rate, role or Docker volume changes were made.

## Install both source folders and restart Metro

1. Stop the OLD Expo/Metro PowerShell window with **Ctrl+C**.
2. Copy the contents of this ZIP's inner `ValhallaFreight` folder into `C:\GitHub\ValhallaFreight`, including **safe-load-mobile**. Keep the existing `.env`, PostgreSQL and document volumes. Do not copy an old node_modules folder into this release.
3. Rebuild the desktop services:

```powershell
Set-Location C:\GitHub\ValhallaFreight
docker compose -p valhallafreight up -d --build
```

4. In a separate PowerShell window launch the new mobile source:

```powershell
Set-Location C:\GitHub\ValhallaFreight\safe-load-mobile
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-SafeLoad.ps1 -ComputerIP 192.168.1.195
```

The launcher runs npm ci and the TypeScript check, then clears Metro's cache. Open Expo Go SDK58 on Android and scan this window's NEW QR code. Close the old project if it remains open. Confirm **App v0.19.7** in the Safe Load header. Server URL: **http://192.168.1.195:8000**; use the existing Manufacturer login. Keep Metro, Docker and the PC running.

Open an unreleased test load, retake BOTH onsite pictures (older temporary captures are not migrated), and submit. Check broker evidence after a rejection or Confirmed/Released after a match. For the complete v0.19.6 workflow, renewal rules and broker contact setup see `V0.19.6_SAFE_LOAD_AUTOMATIC_REVIEW.md`. This fix does not add face/DMV authentication.

This is the full source project, not a live database export or signed app-store binary. Existing local accounts and documents remain in your current volumes. Never run `docker compose down -v`.
