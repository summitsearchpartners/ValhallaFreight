# Valhalla Freight v0.10.0 – Operational Workflow Completion

This release closes key brokerage workflow gaps:

1. Google-verified one-off shipment facilities are automatically saved to Customer 360 after shipment approval.
2. Shipment acceptance invokes the carrier-booking adapter boundary and automatically stores a returned PRO when the carrier returns one; manual PRO entry remains available when a carrier does not.
3. Complete commodity/package/BOL details are captured before shipment acceptance so the carrier API has the operational payload at booking time.
4. Customer 360 Recent Shipment Activity opens the shipment record.
5. Finance disputes create customer, carrier and broker email notifications using account emails. SMTP is optional; local development safely captures the email in the Finance outbox.
6. Network Analytics includes carrier and customer KPI scorecards.
7. Customer margin protection includes optional email billing alerts.
8. Shipments have a document/image vault with role attribution for broker/customer/carrier uploads.

## Direct carrier acceptance / PRO
When a shipment is accepted, Valhalla now invokes the carrier adapter booking boundary immediately. If the carrier response contains a PRO, it is written to the shipment automatically. Dayton's adapter maps the completed shipment payload into its LTL Digital eBOL endpoint; if no PRO is returned or an adapter is unavailable, the existing manual PRO field remains available.
