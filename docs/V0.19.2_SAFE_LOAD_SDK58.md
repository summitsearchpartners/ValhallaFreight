# Safe Load v0.19.2 — Expo Go SDK 58

The mobile project now targets Expo SDK 58 to match the SDK 58 Expo Go installed on the test Android phone. Camera, SecureStore, status bar, React, React Native, TypeScript and React types are aligned with Expo's published compatibility versions. Safe-area handling uses react-native-safe-area-context for the current native runtime.

## Install on the existing PC

1. In the old Safe Load PowerShell/Metro window press Ctrl+C.
2. Extract this ZIP. Copy its `ValhallaFreight/safe-load-mobile` contents into `C:\GitHub\ValhallaFreight\safe-load-mobile`, replacing matching files. Keep the existing root .env and Docker/database running. No desktop rebuild is needed.
3. Open PowerShell and run:

```powershell
Set-Location C:\GitHub\ValhallaFreight\safe-load-mobile
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-SafeLoad.ps1 -ComputerIP 192.168.1.195
```

The launcher checks Node compatibility, installs the pinned package-lock with npm ci, runs TypeScript validation and starts Metro explicitly in Expo Go/LAN mode with caches cleared. Node 22.13+ or Node 24.3+ LTS is supported. Keep the existing local-network TCP 8081 firewall rule enabled. If Windows asks for Node network access, allow it for your test network.

4. Open Expo Go SDK 58 on Android. Scan the new QR code. If needed manually enter `exp://192.168.1.195:8081` in Expo Go.
5. In Safe Load enter TMS server URL `http://192.168.1.195:8000` and the existing Manufacturer account credentials. Do not append /api/v1; the app appends it.
6. The company-scoped queue should show that manufacturer's shipment. Keep PC awake, Docker and Metro running and both devices on the same LAN.

Use this development mode for local HTTP. Preview/production still require HTTPS. This is the Safe Load native application hosted by Expo Go, not a standalone signed APK. If Expo Go later changes its supported SDK, a new SDK upgrade or dedicated development build may be needed.

## Test scenario

Use fictional driver data and a test shipment. Assign the shipment to the company attached to the manufacturer login. Broker/Super Admin generates the carrier submission invitation. Dispatcher submits driver name, license identifiers/expiry, image and VIN. Broker reviews and vouches for the assignment. The manufacturer sees the update in the app, compares the arriving person's physical ID to the photo, and scans the license PDF417 and arriving truck VIN. Wrong data rejects and notifies the broker. After broker resolution/reapproval, a fresh correct scan can match; the same operator must explicitly release freight before verification expires. Confirm the release in desktop Safe Load and shipment records. These checks match submitted data; they do not authenticate an ID against DMV records.
