# v0.19.3 — Super Admin broker customer assignments

## Install

Copy the inner ValhallaFreight project contents into the existing C:\GitHub\ValhallaFreight folder, replacing source files. Keep your existing .env and existing Docker volumes. This project ZIP excludes local environment secrets, Git history and machine-specific dependencies. It is not a database export.

```powershell
Set-Location C:\GitHub\ValhallaFreight
docker compose -p valhallafreight up -d --build
```

Open http://localhost:5173 (or the configured LAN address) and press Ctrl+F5. Existing login accounts remain in your PostgreSQL database. Do not run docker compose down -v.

## Assign customers

1. Sign in as Valhalla Freight Admin (Super User).
2. Open Administration → Users & Company Access.
3. Click Manage broker customers in the Broker customer access card.
4. Choose the broker company / portal. The selector lists its Broker and Broker Admin login emails so you can identify the right workspace.
5. Choose Assign an existing customer / manufacturer, search and select an available company, then Assign customer. Alternatively choose Create a new customer, enter its name and click Create & assign customer.
6. The customer appears in that broker portal's Customers and quoting selectors. Its freight records, Truckload, dashboard/finance and Safe Load records use the same tenant authorization rules. The manufacturer's own account still sees its own company and retains financial privacy.
7. You can also open a Broker/Broker Admin account popup and click Manage customers to jump straight to its portal.
8. Remove opens a confirmation popup. Removing an explicit assignment removes that broker's access immediately on subsequent API requests; it does not delete customer accounts, freight, documents or history.

Newly created customers are customer records only. Create any required login separately using Add user; assigning a customer never changes or creates credentials.

## Manufacturer Test / mantest@mantest.com

Find this email in Users & Company Access. Check its actual stored role and company. If its role is Broker or Broker Admin, its company appears in the broker picker with that email. If it is Manufacturer or Manufacturer Admin, it stays a manufacturer account and will not be treated as a broker just because of its display name. Super Admin can deliberately edit its role/company or create a separate Broker account in the intended broker company. The software does not silently convert roles or guess account identity from an email address.

The uploaded source ZIP does not include the running desktop PostgreSQL account database, so account-specific changes must be made through the running application.

## Access rules

- Only an actual Super Admin outside manufacturer support mode can create/remove broker customer assignments. Broker users, Broker Admins, manufacturers and customers cannot call the management API.
- An independent manufacturer/customer company can be explicitly assigned to one broker company at a time. Remove its existing assignment before moving it to another broker.
- The assigned company's existing child customers inherit that broker access. Manufacturer/customer workspace ownership and login roles remain unchanged.
- Existing customers created under a broker's parent-company ownership retain their previous access. They appear as inherited ownership and are not removed by deleting an unrelated explicit assignment.
- Only companies with Broker/Broker Admin accounts appear as broker targets; new assignments require at least one active broker account. Customer companies cannot themselves be broker workspaces.
- Creating a Broker role in a company currently assigned as another broker's customer is blocked until that assignment is removed.
- Shared assignment grants the broker operational access to that customer company's existing records and records of its children, not just future loads. It is not a transfer between competing broker archives.
- Revocation does not recall previously downloaded documents or clear an already displayed page; a refresh/new API request applies current access.
- Brokers see their own carriers plus the assigned customer's carriers for quoting. Existing customer carrier restrictions still apply. Manufacturer carrier directories and broker payables remain protected.
- Safe Load holds still enforce scans and release. A manufacturer may release its own already-booked shipment without needing access to the broker's private carrier directory.
- Assignment creation/removal is recorded in Super Admin User Activity.

## Database compatibility

One additive broker_customer_assignments table is created by normal startup metadata initialization. 0193_broker_customer_assignments.sql provides the equivalent idempotent PostgreSQL DDL. Existing migrations, data, root company ownership, role values, PostgreSQL and document volumes are retained. No schema reset or database import is required. Safe Load's SDK 58 mobile project remains intact.

## Local acceptance

Assign a test manufacturer to the intended broker. Sign into that broker and verify Customers/Quote Studio/Truckload selectors and Safe Load. Sign into the manufacturer and confirm it sees its own freight with no broker costs or gross profit. Sign into an unrelated broker and verify the records are unavailable. Remove the assignment and refresh the original broker portal; the records should disappear while manufacturer freight remains.
