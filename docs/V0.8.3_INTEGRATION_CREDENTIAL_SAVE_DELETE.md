# Valhalla Freight v0.8.3 — Integration Credential Save & Adapter Deletion

## Credential save reliability
- Fixes the Integration Hub save flow that could throw `Cannot read properties of null (reading 'querySelector')` after the backend had already saved Dayton credentials.
- Captures the form reference before asynchronous API calls, clears credential inputs safely after success, refreshes adapter state, and displays a success notice.
- Saved usernames are shown only as a masked hint.
- Saved passwords remain intentionally blank in the browser and are represented by a clear "saved securely" state.
- Credentials remain encrypted server-side in PostgreSQL.

## Provider adapter deletion
- Imported provider adapters can now be permanently removed from the Integration Hub.
- Delete is available from the provider card and the provider Manage screen.
- A destructive confirmation modal requires typing the exact provider name.
- Deletion removes the adapter registration, saved settings, and encrypted credential record.
- Historical shipment/customer data is not deleted.
- Dayton Freight is a built-in first-party carrier adapter and cannot be deleted; its credentials can still be removed.
