# v0.19.12 — ID photo order and conservative field reading

The phone buttons now follow the warehouse task: **Take ID Front Photo → Take ID Back Photo → Take truck VIN photo → Submit Photos**. Manual guided capture, crop, Accept/Retake and Cancel remain. This release does not claim automatic card detection.

## Reading and decisions

- Front OCR recognizes numbered AAMVA fields (1 surname, 2 given names, 4d license number, 4b expiration), including inline date columns and separate-line labels. Birth and issue dates are not substituted for expiration.
- OCR tries all four orientations with sparse-text and block-text modes, contrast enhancement and upsampling of smaller images. It selects a whole-card candidate rather than filling missing identity fields from the dispatcher assignment.
- Back-photo PDF417 decoding tries contrast/quiet-zone, upsampled and inverted variants and two thresholding methods. It preserves raw barcode control characters for AAMVA field parsing. A photo cannot recover barcode detail that was never captured.
- The broker evidence panel and phone distinguish unreadable/incomplete evidence from read identity data that differs. Neither is silently approved.
- Existing renewal support remains: a later valid expiration can be accepted when license number/issuer, first/surname and truck VIN match. Optional middle names and suffix formatting are tolerated. A changed number or issuer still requires independent broker verification, even if the name is the same.
- An unreadable submitted back photo remains held; it is not ignored. Prior rejected arrivals still require broker resolution. Callback contact, broker notifications, encrypted evidence, confirmation receipts and custody history remain.

This compares extracted fields; it does not authenticate a person, face, document authenticity or DMV record. No OCR can promise perfect extraction. The supplied screenshots are small thumbnails and did not yield complete identity fields in local testing. They were used privately for diagnosis and are not included in this project. Test clear original camera photos and representative current/older cards on your actual phone before operational use. Do not relax the hold simply to make a test pass.

## Install and test

1. Preserve your local .env and existing PostgreSQL/document volumes. Copy the ZIP's inner ValhallaFreight contents into C:\GitHub\ValhallaFreight. This source ZIP does not contain your live database or uploaded identity photos. Existing migrations and database initialization files are preserved.
2. Stop the old Metro window with Ctrl+C. Rebuild the backend and frontend:

```powershell
Set-Location C:\GitHub\ValhallaFreight
docker compose -p valhallafreight up -d --build
```

3. In a separate PowerShell window:

```powershell
Set-Location C:\GitHub\ValhallaFreight\safe-load-mobile
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-SafeLoad.ps1 -ComputerIP 192.168.1.195
```

4. Scan the new Metro QR in Expo Go SDK58. Verify **App v0.19.12**. Keep TMS URL http://192.168.1.195:8000 (change the IP if your PC's address changed).
5. Use a new test arrival: accept front, back and VIN photos in that order. Inspect retained crops before Submit Photos. Test a readable matching card, valid renewed expiration with unchanged identity, deliberately wrong VIN, unreadable back, and broker resolution after rejection. Verify the stored evidence and custody record as both broker and warehouse. Existing rejections will not auto-clear from better photos.

Do not delete Docker volumes. Physical Android camera testing, original high-resolution user photos and a live PostgreSQL/Docker run were not available in this build environment.
