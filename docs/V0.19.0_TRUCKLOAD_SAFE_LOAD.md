# v0.19.0 — Truckload Command and Safe Load

## Install without losing data

Back up your running installation. Keep the SAME project directory, Compose project name, `.env`, database volume and document volume. Copy this application's files over your working folder, then run:

```powershell
Set-Location C:\GitHub\ValhallaFreight
docker compose -p valhallafreight up -d --build
```

Open http://localhost:5173. No volume deletion, database reset or account reseeding is needed. Four new tables are added by the existing startup `metadata.create_all` mechanism. The equivalent idempotent PostgreSQL DDL is `backend/migrations/0190_truckload_safe_load.sql`; existing tables/migration logic are unchanged. Cancellation revokes pending carrier links and prevents release; a cancelled Safe Load shipment must be replaced rather than reactivated. Existing shipments are grandfathered until Safe Load is explicitly enabled before pickup. ALL newly created operational shipments receive a hold, including LTL shipments.

## Truckload Command — Broker, Broker Admin and Super Admin

- Create a truckload quote with customer, reference, equipment, commodity, total weight, package quantity, customer price, facility-local appointments, contacts, instructions and one pickup and up to 19 ordered delivery stops. Reefer quotes require a Fahrenheit temperature range.
- Edit unbooked quotes when the requirements change. Editing invalidates their existing bids so old rates cannot be silently reused. Booked quotes are locked.
- Enter carrier buy bids and expiration times; compare price and gross profit, select a current bid, and download the carrier rate-confirmation PDF.
- The history panel uses ONLY your own booked loads matching equipment and 3-digit origin/destination ZIP regions. Empty history is shown explicitly. There is no simulated market index.
- Book into the existing shared shipment/BOL/document/invoice workflow. Repeat booking requests return the same shipment. Truckload is a negotiated bid workflow; it does not run through an LTL carrier rating adapter.
- No tender is sent automatically: the carrier submission is labeled `manual tender pending`. Confirm acceptance directly with the carrier. Load boards, live market indices, EDI/DFM, automated carrier outreach, GPS/check calls and automatic document recognition are not connected in this release.
- Additional warehouse pickups must be separate shipments in this release so each has its own enforced Safe Load decision. A per-stop multi-pickup release model is not implemented; the API rejects such routes.
- Complete stops sequentially after Safe Load release. Final delivery advances the shared shipment; the existing broker invoice action remains available in Shipment Control Tower. Times entered on stops are facility-local, without automatic cross-timezone routing calculations.
- Manufacturer accounts do not get the broker truckload desk or its buy-price/GP information. They see assigned shipments and their Safe Load status. Existing broker company/customer scope still applies; unrelated manufacturers are not exposed to brokers.

## Safe Load workflow

1. Book an LTL shipment in Quote Studio or book a truckload quote. It appears in **Safe Load** automatically with a HOLD.
2. A broker creates a load-specific carrier submission link, then shares it with the known carrier dispatcher through their normal verified contact channel. No email/SMS is sent automatically. Tokens expire in 24 hours, are stored as keyed hashes, and live in URL fragments so they are not sent as URL paths/referrers. Creating a new link revokes the previous link.
3. The dispatcher submits the driver's full name, license number, issuing state/province, expiry, a clear license photo (JPEG/PNG/WebP, under 8 MB / 16 megapixels), and 17-character truck VIN. A new assignment increments its revision and invalidates prior approval/scans.
4. The broker independently confirms/vouches for the assignment through the known carrier contact and records how it was verified. A packet is not approved just because a link was used.
5. The warehouse worker signs into the web Safe Load page or the native mobile app using their existing assigned Manufacturer/Manufacturer Admin/Broker/Super Admin account. Accounts are still created only by Super Admin. Staff see only their authorized company shipments; this release does not introduce separate per-dock or warehouse-only roles.
6. Compare the arriving person and physical ID against the submitted photo. Scan the physical license PDF417 and the truck's VIN barcode. On the web, a keyboard barcode scanner can populate the two scan fields. Native camera scanning is in the phone/tablet project.
7. The server compares license number + issuer, the license name/expiry, VIN, assignment revision and the operator's visual-comparison attestation. A mismatch gives **REJECTED / DO NOT RELEASE**, persists an audit event, creates a critical broker notification and invalidates approval. The current dispatcher assignment must be corrected if necessary, independently approved again, and rescanned. There is NO force-green or Super Admin bypass endpoint.
8. A successful scan gives **ACCEPT / MATCHED — RELEASE PENDING** for 10 minutes, tied to that operator and assignment version. That same operator must click **Release freight** online. Only the successful release response advances pickup and records a tracking event. Expiry/reassignment/rejection prevents release; offline devices cannot authorize a release.

Manufacturer and broker portals use an authenticated event stream for prompt updates (normally about one second while connected). The native foreground queue refreshes about every three seconds. Events are persistent, including photo access, approval, rejection and release. Mobile background push/SMS/email alerts are not implemented; keep the broker portal open for event-stream alerts.

Actual Muse bookings are also visible to the Super Admin-designated Muse Broker Admin company through Safe Load. This exception is limited to actual Muse booking shipment IDs and Safe Load routes. Other brokers do not receive cross-company access. Rejection alerts are recorded for both the manufacturer and designated Muse company.

## What verification does and does not prove

Safe Load compares recorded identity/vehicle data and requires a human visual check. It does NOT verify a license against a DMV, establish CDL status, authenticate a document, perform face recognition/liveness detection or validate VIN ownership. Reading a barcode is not proof that an ID is genuine. Supported license scans are AAMVA PDF417 records with DAQ/DAJ/DAC/DCS/DBA fields; some older/non-North-American IDs require a future supported verification method. Unsupported/unreadable scans remain blocked.

The hold is enforced in backend shipment/timeline changes, including Super Admin status edits and carrier-tracking updates. It controls the TMS release decision; it does not physically lock a warehouse door. Warehouse staff must follow the release procedure. Do not treat this initial release as a certified fraud-prevention system until real device/document/warehouse acceptance testing is completed.

## Data protection and operations

- License numbers are not returned by APIs; only their last four characters are shown. Matching uses keyed HMAC digests. License images are encrypted at rest in the existing document volume and served only through authenticated, scoped endpoints with `Cache-Control: no-store`.
- Use HTTPS and a stable, strong `INTEGRATION_SECRET_KEY` before collecting real IDs. Preserve that key with the database and encrypted document backups. Local Docker HTTP is for fictional test data only.
- No barcode payloads are written to the audit log. Scans live temporarily in client memory and are cleared after verification or when changing assignments. Mobile access tokens use OS secure storage, not plain local files. Authorized users can view the complete submitted license photo because that is necessary for the requested comparison.
- Define retention, access review, incident handling and deletion procedures for driver identity documents before rollout. This release does not automatically purge released license photos; database and encrypted-volume backups contain identity data too. Restrict who receives those backups. The Super Admin account is not an alternative way around a rejected warehouse check.
- Broker vouch notes are audit content: do not paste full license numbers or raw scans into notes.

## Phone / remote dispatcher connectivity

A localhost carrier link works only on the computer that created it. For a local-network test, set these root `.env` values using your computer's actual LAN IP, restart/rebuild the frontend/backend, open the TMS at that LAN address, and THEN create the invitation:

```dotenv
VITE_API_URL=http://192.168.1.20:8000/api/v1
CORS_ORIGINS=http://localhost:5173,http://192.168.1.20:5173
```

The example IP is a placeholder. Allow the needed ports only on your trusted private test network. Native development uses the API server URL http://192.168.1.20:8000; the carrier browser form uses http://192.168.1.20:5173. Native production builds require HTTPS. Internet dispatchers need a deployed HTTPS frontend/backend; a private LAN address or localhost cannot serve outside carriers. Compose now reads these two `.env` settings while retaining localhost defaults and the original database/document volume names. Demo exports deliberately restore localhost API/CORS values for a self-contained laptop demo.

## Acceptance walkthrough

Use fictional data for initial testing. Create a broker truckload quote, enter/select a carrier bid, book, open Safe Load, and submit a fictional driver via the invitation form. Confirm a normal shipment status edit to in-transit fails while held. Approve the packet, scan the wrong VIN and verify RED rejection and the broker alert. Correct/vouch/rescan, verify the current operator can release, and prove stop completion → BOL/documents → customer invoice. Repeat on a new LTL shipment and with separate company accounts. Physical camera, real AAMVA cards, connectivity loss, actual truck VIN labels, photo readability, devices and warehouse procedures require on-device field tests before production.

Tai's public FTL page informed the operations layout (https://tai-software.com/solutions/full-truckload-ftl/). This release implements its own local order/bid/history workflow plus Safe Load; it does not claim feature parity or superiority to Tai's connected products.
