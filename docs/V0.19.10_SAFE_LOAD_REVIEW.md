# v0.19.10 — Single-photo review and real barcode scanner sessions

## Why the previous screen kept taking pictures

v0.19.9 used repeated still photographs as readiness/decoder samples. Those calls could trigger the physical shutter and continue indefinitely when no clear document or barcode was detected. This release removes that repeating photo loop entirely.

The ID photo path now has a bounded state machine: camera → one candidate → review → Accept Photo or Retake. No capture can run while a candidate is being reviewed or saved. Only Accept Photo attaches the image to the load and records the existing accepted-capture event; final identity QA still runs after Submit Photos.

## Photo behavior

- Open **Take driver ID photo** and position the physical ID inside the card outline. One quiet candidate/alignment check runs after a short positioning delay. If the existing server checker finds a centered, sufficiently sized, sharp and adequately lit card, that single image freezes on the review screen.
- If the check cannot find a clear card, it stops and explains why. It does **not** keep taking pictures. Realign and tap **Check Alignment** for one further check, or use **Take Photo**. This is a bounded candidate check, not a continuously running native rectangle detector. Device policies can still enforce a shutter sound for an individual capture.
- **Take Photo** takes exactly one manual candidate and opens review. It does not require the readiness heuristic to pass; final QA still blocks unreadable/mismatched identity evidence.
- **Accept Photo** keeps that exact picture and returns to the shipment. A failed save leaves the same preview available for retry. The accepted file is not deleted when the camera screen unmounts.
- **Retake** deletes the rejected candidate and reopens the camera for a fresh attempt. It rearms one automatic check for an ID photo. VIN photos remain one-shot manual captures with the same review controls.
- **Cancel** or Android Back discards an unaccepted candidate and returns to the load. A previously accepted photo remains until a replacement is accepted or normal existing cleanup occurs. Stale/closed assignments cannot adopt a late capture.

## Barcode scanning is separate from taking photos

The default on a supported device is Expo's native barcode scanner (Google code scanner on Android; supported native scanner on iOS). A result subscription is registered before launch and remains active until an actual barcode event arrives or the scan is cancelled/times out. Launch completion is not assumed to be the barcode result; this prevents the earlier event race. Duplicate events are ignored while that one result is decoded.

- For the back of a DL, scan the entire **PDF417**. The backend validates and extracts the identity fields. A successful result shows **BARCODE READ**, the name, issuing state/license ending, expiration and DOB when encoded. Tap **Use Scanned Data** to return those fields to the shipment, or **Scan Again**.
- VIN scan uses the existing canonical 17-character VIN validation. A valid result displays the actual VIN before Use Scanned Data. Wrong or malformed values stay errors, not fabricated matches.
- If the native scanner is unsupported, unavailable or closed without a usable result, select **Use Live Preview**. That preview uses native live barcode events with autofocus/torch/zoom and takes **no photographs automatically**.
- **Decode One Frame** is a deliberate fallback: it captures one transient frame only when tapped and asks the authenticated backend's real barcode decoder to read it. There is no interval or automatic shutter loop. Unreadable frames show an error and allow an explicit retry.
- Native scan models/Google Play Services may need to initialize on first use. Cancel/Back in the native scanner returns to the app. A no-result timeout gives retry/live-preview options. Do not claim a successful scan until the extracted fields actually appear.

Both required onsite evidence photos are still mandatory. Use Scanned Data is input selection, not release authorization. Submit Photos still compares scanned/photo fields, expiry, driver assignment and truck VIN; a failure keeps the hold and notifies the broker. Existing rejected loads remain broker-controlled until resolved. Government/facial/VIN ownership authentication is not added.

The current camera APIs are documented at https://docs.expo.dev/versions/v58.0.0/sdk/camera/ . This release keeps Expo SDK58; it does not require a new app-store publication.

## Update desktop and mobile together

Preserve `.env`, existing PostgreSQL/document volumes and all current accounts. Copy the ZIP's inner ValhallaFreight project over `C:\GitHub\ValhallaFreight`, including safe-load-mobile. Stop old Metro with Ctrl+C.

```powershell
Set-Location C:\GitHub\ValhallaFreight
docker compose -p valhallafreight up -d --build
```

In a separate PowerShell window:

```powershell
Set-Location C:\GitHub\ValhallaFreight\safe-load-mobile
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-SafeLoad.ps1 -ComputerIP 192.168.1.195
```

The launcher installs the updated pinned mobile dependency tree and clears Metro. Scan the NEW QR code in Expo Go SDK58 and verify **App v0.19.10**. Server URL stays `http://192.168.1.195:8000`. Retake photos for your test and use a NEW fictional shipment to test automatic QA release. Never run `docker compose down -v`. This ZIP is complete source, not a copy of your live database or a signed APK.

## Verification and acceptance

Regression tests exercise one automatic attempt per round, preview-before-accept, duplicate capture prevention, Retake deletion, failed-save retry, cancellation, late callbacks and accepted-image ownership across screen unmount. Native scanner bridge tests cover launch-before-result ordering, duplicate events, cancellation and successful retries. These are deterministic bridge/state tests, not a claim of a physical phone camera test.

Backend camera/barcode/photo QA tests continue to use actual generated barcode images and local OCR. Existing backend role/company access, evidence encryption, confirmation numbers and custody rules are unchanged. No schema, migrations, seed data, Compose volume names or carrier integrations changed. See RELEASE_CHECKS.md for current results.

On your phone, leave an unaligned ID in view and confirm there is no repeating shutter. Align it and take/check once, then confirm the image freezes until Accept Photo or Retake. Accept and verify the same image appears on the load. Use the fictional PDF417/VIN PNGs in docs/safe-load-test-photos to verify that barcode fields appear and survive Use Scanned Data → Submit Photos → final QA. Real hardware, lighting, first-use native scanner availability and card layouts still require local testing.
